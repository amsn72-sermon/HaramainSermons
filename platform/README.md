# منصة ترجمة خطب الحرمين الشريفين

نسخة تشغيلية للمنصة والموقع العام. الخادم Supabase مستضاف ذاتيًا في الرياض (قاعدة البيانات والحسابات والتخزين)، والواجهة على Cloudflare Pages.

```
platform/
├── app/                      الموقع كاملًا (ملفات ثابتة، بلا خطوة بناء)
│   ├── config.js             ← رابط Supabase ومفتاح anon (عدّله قبل النشر)
│   ├── _headers              سياسات الأمان (CSP وغيرها) لـ Cloudflare
│   ├── _redirects            توجيه كل المسارات إلى التطبيق
│   └── js/ css/ assets/ vendor/
├── selfhost/                 تثبيت الخادم على Oracle Cloud الرياض + النسخ إلى جدة
└── supabase/
    ├── migrations/0001_init.sql   المخطط والصلاحيات والبيانات الأولية
    └── tests/                     اختبارات سير العمل والصلاحيات (٣٤ اختبارًا)
```

- `/` الموقع العام: البث المباشر، أحدث الخطب، الأرشيف، والترجمات المكتوبة المعتمدة.
- `/start` «اختر وجهتك»: الإدارة، المترجم، المستفيدون — كما في النسخة الأولى.
- `/app` منصة الفريق: المتابعة، إضافة مادة، مهامي، الأرشيف، الفريق، اللغات، الخطباء، سير العمل.
- `/register` تسجيل المترجمين، ثم يفعّلهم المنسق.

لا يمس هذا المجلد ملفات المستودع الأخرى: `index.html` القديم، ومزامنة أرشيف يوتيوب، و`sermons.json` الذي يقرؤه التطبيق من GitHub Pages — كلها تعمل كما هي.

## خطوات التشغيل

### ١. الخادم (داخل المملكة)

Supabase السحابي لا يملك منطقة في الشرق الأوسط، لذلك تُشغَّل نسخته الرسمية مفتوحة المصدر على خادم Oracle Cloud في الرياض، والنسخ الاحتياطية في جدة. الخطوات كاملة في **[`selfhost/README.md`](selfhost/README.md)**، وخلاصتها:

1. خادم Ubuntu في الرياض، وسجل `api` في Cloudflare يشير إليه (DNS only).
2. `sudo sh selfhost/install.sh`: يثبّت كل شيء ويطبّق `0001_init.sql` ويطبع مفتاح anon.
3. ضع المفتاح في `app/config.js`؛ الرابط مضبوط مسبقًا على `https://api.haramainsermons.com`.
4. `selfhost/backup.sh` للنسخ الليلي المشفّر إلى جدة.

> لا تضع مفتاح `service_role` ولا كلمة مرور قاعدة البيانات في أي ملف داخل `app/`. كل ما في هذا المجلد يصل إلى متصفح الزائر.

### ٢. Cloudflare Pages

**Workers & Pages ← Create ← Pages ← Connect to Git**، ثم اختر المستودع `HaramainSermons`:

| الإعداد | القيمة |
| --- | --- |
| Production branch | `main` |
| Framework preset | None |
| Build command | *(فارغ)* |
| Build output directory | `platform/app` |

بعد الإنشاء: **Settings ← Builds ← Build watch paths ← Include paths**: `platform/app/*`

هذه الخطوة مهمة: مزامنة أرشيف يوتيوب ترفع تحديثًا إلى `main` كل ١٥ دقيقة (قرابة ٢٩٠٠ مرة شهريًا)، والخطة المجانية لـ Pages تسمح بـ٥٠٠ عملية نشر شهريًا. بدون هذا القيد تستنفدها المزامنة وحدها.

### ٣. الدومين

1. في Cloudflare: **Add a domain**، ثم غيّر خوادم الأسماء (Nameservers) لدى الموقع الذي اشتريت منه الدومين إلى الخادمين اللذين تعطيك إياهما Cloudflare. الانتقال يأخذ من دقائق إلى ٢٤ ساعة.
2. في مشروع Pages: **Custom domains ← Set up a custom domain** وأدخل الدومين.
3. `app/_headers` يسمح بالاتصال بـ`api.haramainsermons.com` فقط. إن تغيّر دومين الخادم فعدّله هناك وفي `config.js`.

### ٤. أول مدير للمشروع

1. افتح `https://دومينك/register` وسجّل حسابك، ثم أكّد بريدك.
2. في Studio ← SQL Editor (انظر `selfhost/README.md` لطريقة فتحه):
   ```sql
   update public.profiles set role = 'manager', status = 'active' where email = 'بريدك';
   ```
3. من الآن تفعّل بقية الفريق من شاشة **فريق العمل**، ولا حاجة لـ SQL.

## ما تغيّر عن النسخة التجريبية

التصميم محفوظ كما في النسخة الأولى: الشعاران (الهيئة والرئاسة) في الترويسة، المظهر الداكن أصلًا مع زر الفاتح، القائمة الجانبية بترتيبها وأسمائها، صفحة «اختر وجهتك»، وتذييل النقش. التغيير في المنطق والبيانات وفق ملاحظات المراجعة:


| الملاحظة في تقرير المراجعة | المعالجة |
| --- | --- |
| تحديث الصفحة يمحو كل شيء | قاعدة بيانات دائمة على خادم داخل المملكة |
| نافذة التأكيد تسبق التحقق | `stage_blockers` يُسأل أولًا؛ النافذة لا تظهر لطلب سيُرفض |
| العدّاد يبدأ من الإسناد | مهلة استلام مستقلة، ووقت المرحلة يبدأ من قبولها |
| المواعيد لا تُعاد جدولتها | كل مرحلة تُحاسَب على مدتها من لحظة بدئها |
| المسار المختصر يخسر وقت المراحل المتجاوزة | يُعاد توزيعه على مراحله بالنسبة نفسها |
| لا أثر للتأخير بعد انقضائه | `late_seconds` لكل مرحلة وللاستلام، ومؤشر «سُجّل فيها تأخير» |
| الاعتماد لا ينشر شيئًا | الاعتماد النهائي ينشر على الموقع العام، والمدير يستطيع الإخفاء |
| أسماء اللغات مختلفة بين التطبيقين | جدول لغات واحد يقرؤه الاثنان |
| قيم إنجليزية خام في الواجهة | كل الأدوار والحالات معرّبة |
| المترجم يراجع ترجمته دون تنبيه | تنبيه عند الإسناد |
| «تبديل الحساب» لا ينهي الجلسة | الخروج يلغي الرمز ويعيد بناء الصفحة |
| لا تحقق من رقم الهوية | ١٠ أرقام تبدأ بـ١ أو ٢، في الواجهة وقاعدة البيانات معًا |
| نموذج إضافة المادة طويل | ثلاث خطوات مع حفظ مسودة تلقائي |

## لم يُبنَ بعد

- **الإشعارات الفعلية** (بريد، واتس آب) عند الإسناد والتأخير. تحتاج Edge Function وحساب واتس آب للأعمال.
- **استيراد الفريق من Excel**: إنشاء حسابات جماعيًا يتطلب مفتاح الخدمة، فمكانه Edge Function لا المتصفح. التسجيل الذاتي مع التفعيل يغني عنه مؤقتًا.
- **التسجيلات الصوتية**: حاوية `audio` عامة القراءة بمسارات عشوائية يصعب تخمينها. إن لزم منع الوصول قبل النشر تمامًا، تُنقل إلى حاوية خاصة مع روابط موقّعة.

## الاختبارات

`supabase/tests/workflow_test.sql` يشغّل دورة كاملة على PostgreSQL محلي ويتحقق من ٣٤ قاعدة: الصلاحيات، رفض المدخلات الخاطئة، توزيع الوقت، تسجيل التأخير، الإعادة بسبب، والنشر. `supabase_shim.sql` يحاكي الحد الأدنى من بيئة Supabase لذلك.
